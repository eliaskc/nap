# iOS apps on Nap

Nap also hosts native iOS apps in SwiftUI, for things a web page cannot do, such as an onboarding flow that must feel native or a game that should feel at home on the phone. You need a Mac with Xcode, git, Node 20+, and Tuist (mise install, from the repo's mise.toml). Nap signs the builds; you never sign anything.

This Nap has one iOS app on Nap, `{{testFlightApp}}`: the launcher, which people install from TestFlight. Every app lives inside it. Nap uploads each build of the launcher to App Store Connect, Apple processes it for a few minutes, and testers install or update it in the TestFlight app. https://{{rootDomain}}/apps shows when a build is ready. People get the launcher from Get the app on the dashboard; send anyone who cannot to {{admin}}.

- The repo holds a Tuist project: the launcher in Launcher/, and one folder per app in Apps/<slug>/ (app.json, and Sources/ with a public struct AppView: View). Read the repo's AGENTS.md before you change it.
- Get the source: node nap-publish.mjs app clone {{testFlightApp}} [dir]. Pull before you start (node nap-publish.mjs app run {{testFlightApp}} -- git -C <dir> pull nap main), and run scripts/generate after every pull. If it does not exist yet, create it from the template once: node nap-publish.mjs app init {{testFlightApp}} [dir] --title 'Name'.
- A new app is a new folder in Apps/: copy Apps/hello. Never make a second app on Nap.
- Test in the Simulator while you work (xcodebuild -scheme Launcher -sdk iphonesimulator, or Xcode). Simulator builds cannot be published.
- Publish: commit, then scripts/publish 'What changed, for testers'. It builds the launcher for iPhone without signing, pushes HEAD to main, and uploads the build with that commit. Nap signs it, gives it the next build number, and sends it to TestFlight. Never force-push main.
- A publish answers 409 "source_not_head" when someone pushed after you: pull, build, and publish again. "source_not_descendant" means your history drops a published commit: merge it back in.
- Keep the launcher's app icon (Launcher/Resources) and ITSAppUsesNonExemptEncryption in Project.swift: TestFlight refuses builds without them.
- Permissions, capabilities, and other Info.plist keys go in the app's app.json, never in Project.swift: "permissions" are Info.plist usage strings ({"NSCameraUsageDescription": "Why, in a sentence"}), "infoPlist" holds any other keys ({"UIBackgroundModes": ["audio"], "NSBonjourServices": ["_my-app._tcp"]}), and "capabilities" are names such as ["push-notifications", "healthkit"]. The repo's AGENTS.md lists them. Nap turns capabilities on when it signs; what it cannot turn on, the publish answer lists under capabilityWarnings and the launcher shows on the app. Tell the user about those. Networking, WebSockets, and audio need nothing, except audio that keeps running when the phone locks (UIBackgroundModes in "infoPlist").
- Nap data from the app: the app cannot pass Cloudflare Access, so it uses a Nap token like an agent. Sign in with the device flow from the `api` topic: POST /\_nap/api/auth/device, open https://{{rootDomain}}/connect?code=<user_code> in an ASWebAuthenticationSession (or Safari) for the person to approve, poll POST /\_nap/api/auth/token, and keep the token in the Keychain. Then send Authorization: Bearer <token> to https://{{rootDomain}}/\_nap/api/naps/<id>/data/<collection>[/<doc>], /live, /channel/<name> (WebSockets: URLSessionWebSocketTask with the header), and /rtc (ICE servers for WebRTC). They work exactly like /\_nap/data, /\_nap/live, /\_nap/channel, and /\_nap/rtc on the nap's own host, so the app shares data and channels with the web version. GET /\_nap/api/people returns everyone's name and look (shape and colour), like nap.people() on the web. On 401 with code "invalid_token", sign in again; with "inactive", ask the person to open https://{{rootDomain}} in Safari.
- Tell the user the build number, that it reaches TestFlight in a few minutes, and that https://{{rootDomain}}/apps shows when it is ready.

In the commands, `nap-publish.mjs` is `/tmp/nap-publish.mjs` (see the main instructions).
